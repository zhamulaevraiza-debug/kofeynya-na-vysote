# Кофейня на высоте — Glass

Прототип мобильного приложения кофейни: клиентская часть и панель бариста в одном
файле, без сборки и зависимостей — чистый HTML/CSS/JS. Оформление перенесено из
макета Claude Design «Кофейня на высоте - Glass»: матовое стекло, тёплое золото,
Cormorant Garamond в заголовках и фотография интерьера как подложка.

## Запуск

**С сервером** (нужен для `index.html` — фотографии лежат рядом в `assets`):

```bash
python -m http.server 8731
```

Затем откройте http://localhost:8731

**Без сервера** — откройте «Кофейня на высоте — автономная.html» двойным кликом.
Все фотографии вшиты внутрь, файл работает откуда угодно и пересылается целиком.
Обычный `index.html` при открытии прямо с диска покажет пустые места вместо фото:
относительные пути в режиме `file://` не работают — для этого и сделана копия.

Пересобрать автономную копию после правок `index.html`:

```bash
python build-standalone.py
```

## Публикация

**Сайт:** https://zhamulaevraiza-debug.github.io/kofeynya-na-vysote/

Хостинг — GitHub Pages из ветки `main` этого репозитория, каталог `/ (root)`.
Каждый `git push` в `main` переиздаёт сайт сам, обычно в течение минуты.
Публикуется `index.html` вместе с папкой `assets`; снимки напитков он берёт с
фотостока напрямую.

Есть и приватная копия на claude.ai:
https://claude.ai/code/artifact/cf537962-6738-4b6c-9605-047f5378f686
(ссылку раздаёт кнопка «Поделиться» на самой странице).

Для площадок, где страница живёт одним файлом, нужна копия, у которой внутри вообще все картинки: площадки обычно
запрещают загрузку с чужих доменов, и снимки напитков с фотостока не открылись бы.
Такую копию собирает отдельный скрипт (скачанное кэшируется в `.imgcache`):

```bash
python build-web.py
```

Он делает `web.html` — самодостаточный файл, который можно положить на любой
статический хостинг. Дополнительно из него готовится `artifact.html`: то же самое
без внешних тегов документа, потому что площадка оборачивает страницу в свой каркас.

## Вход

- **Клиент** — «Пропустить» (гостевой режим) или регистрация: она даёт +500 баллов.
- **Бариста** — ссылка «Вход для персонала» внизу экрана входа. Выберите
  сотрудника и введите его PIN (Ахмад — `2412`, Муса — `7391`; пока приложением
  пользуется один человек, коды подписаны прямо под именами на экране входа —
  перед передачей персоналу эту подпись стоит убрать). После 5 неверных попыток
  ввод блокируется на 30 секунд.

## Что внутри

**Клиент** — стартовый экран, вход и регистрация, главная с промо и галереей
«Атмосфера гор», меню по категориям, карточка товара с объёмом и добавками,
корзина со скидкой 10%, бронь столика, заказы с трекером статусов, бонусы,
избранное, история заказов, адреса, карты оплаты. Темы — тёмная, светлая,
системная и три «атмосферные» (Карамель, Мокка, Хвоя) по палитре заведения;
переключатель — кнопка справа в шапке главной и раздел «Настройки» в профиле.

**Панель бариста** — главная со сводкой смены, реестр заказов
(«Новые → В работе → Готовы → Выполненные»), брони, меню и остатки, смены,
клиенты, финансы, уведомления, профиль. Новое блюдо добавляется с фотографией
(камера или галерея): снимок обрезается в квадрат и сжимается прямо на устройстве,
поэтому в меню и на карточке товара выглядит как остальные; фото можно заменить
по кнопке «+» на миниатюре в списке позиций.

Обе половины работают на общем состоянии: заказ клиента сразу виден бариста, а
смена статуса возвращается клиенту уведомлением и начислением баллов.

## Как устроено

Полная перерисовка на каждое изменение состояния — разметка собирается строками,
затем новое дерево морфится в старое, поэтому не сбрасывается прокрутка, не
теряется фокус в поле и не перезапускаются анимации.

- `S` — всё состояние; `setS` меняет временное, `set` пишет ещё и в хранилище
- обработчики кладутся в массив, в разметку уходит их номер (`data-c`)
- палитра задана переменными на корне, тема меняется подстановкой строки
- стекло навешивается одним правилом на всё, что красится через `var(--card)`

Состояние хранится в localStorage браузера под ключом `knv2`; сервер ничего не
сохраняет. Подробный разбор приёмов — в справочнике проекта.

Что происходит с данными при большом объёме (проверено стресс-тестом на 1000
заказах и 300 бронях за смену):

- две вкладки одного браузера (клиент и панель) не затирают друг друга: перед
  каждой записью состояние сливается с тем, что записала соседняя вкладка —
  заказ берётся тот, что дальше по цепочке статусов, бронь — с принятым решением;
- закрытые заказы старше недели теряют журнал и состав для повтора, старше
  месяца — удаляются; потолок 3000 записей, броней — 500 за 30 дней;
- номер заказа идёт из счётчика, поэтому после очистки архива не повторяется;
- при переполнении хранилища данные сжимаются жёстче и запись повторяется;
  если места всё равно нет — внизу появляется красная плашка, пока запись не
  восстановится, а всё сделанное остаётся в памяти вкладки;
- длинные списки (архив заказов, клиенты, брони) рисуются порциями по кнопке
  «Показать ещё», кнопка статуса защищена от двойного клика.

## Границы прототипа

Сервера нет — обе половины работают с одним localStorage, поэтому заказ с телефона
не увидит бариста за стойкой. Вход условный: пароль клиента никуда не отправляется и
не проверяется, а PIN персонала сравнивается прямо в браузере — это витрина интерфейса,
а не система доступа. Из карты сохраняются только платёжная система и последние
четыре цифры (`{ brand, last4 }`) — номер, срок и код не записываются никуда.
Фотографии напитков грузятся с фотостока, фотографии заведения лежат локально.
